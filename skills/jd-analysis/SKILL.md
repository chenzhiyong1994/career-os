# JD Analysis

## 概览

把岗位描述转成结构化的 `JD scorecard`，供后续简历优化和作品集取证使用。把 JD 当作证据来源，而不是要复读的营销文案。

## 工作流

1. 记录来源：公司、岗位名称、地点、级别、雇佣类型、URL 和分析日期。
2. 区分明确要求和推断信号。
3. 按类别整理要求：技能、领域知识、职责、工具、级别、软技能和工作条件。
4. 按招聘权重排序：`must-have`、差异化加分、背景信息或噪音。
5. 生成评分卡，并保留来自 JD 的证据锚点或转述依据。
6. 为 `resume-tailor` 和 `portfolio-curator` 输出可用输入。

## 推荐输出结构

除非用户另有要求，优先输出：

- 岗位概览
- 硬性要求
- 加分项
- 职责和成功信号
- 关键词和同义表达
- 级别与职责范围信号
- 候选人需要补充的证据
- 风险、缺口和需要追问的问题
- 简历/作品集取证 brief

## 分析规则

- 不要把每个重复词都当作重点。按位置、具体程度和业务后果判断权重。
- 保留不确定性。推断出来的信号要标记为“推断”。
- 把模糊要求翻译成可验证的证据需求。例如 “cross-functional collaboration” 应转成涉及利益相关方、取舍和交付结果的经历。
- 注意岗位膨胀：JD 可能同时写了初级执行和高级 ownership，要明确指出这种矛盾。
- 如果 JD 来自公开网页，只有在用户要求核实最新信息，或信息时效性会影响判断时，才联网核验。
