# 公开发布前的隐私与脱敏清单

Career OS 会处理高度个人化的求职材料。公开示例的目标不是“看起来像真的”，而是在不携带真实身份和商业机密的前提下，保留足够的结构来复现工作流。

## 默认不公开的内容

- 真实姓名、手机号、个人邮箱、住址、证件号码、生日和精确地理位置；
- 头像、签名、二维码、作品集私链、带身份参数的分享链接；
- 招聘人员姓名与联系方式、申请编号、候选人 ID、私有 JD 页面；
- 未公开公司、客户、学校或产品名称，以及能组合识别主体的业务细节；
- 未公开收入、转化率、成本、用户量、效率、排名和实验结果；
- 内部截图、原型、PRD、数据库结构、会议记录、聊天记录和导出文件；
- API key、Token、Cookie、私钥、本机账号配置和绝对路径。

## 推荐的脱敏方式

1. **优先合成，不做逐字打码。** 用虚构角色、虚构组织和虚构指标重建最小案例，避免遗漏隐藏字段。
2. **保留结构，不保留指纹。** 可以保留“B 端 SaaS”“跨端工作流”“指标待确认”等结构，但删除独特公司名、时间线和组合特征。
3. **数字使用明确占位。** 使用 `<待确认>`、`[metric]` 或显式标注的 synthetic value，不用真实数字轻微扰动冒充脱敏。
4. **链接整体替换。** 使用 `https://example.com`，不要只删除查询参数后保留可识别路径。
5. **图片重新制作。** 内部截图应改成抽象示意图或合成界面，不要仅在截图上覆盖几个文本框。
6. **文件名同样脱敏。** 姓名、公司和岗位信息不应残留在文件名、目录名或压缩包名中。

## 提交前检查

### 工作树与暂存区

```bash
git status --short
git diff --cached --stat
git diff --cached
```

逐个确认新增文件，尤其关注 PDF、图片、压缩包、CSV、导出 HTML 和隐藏目录。`.gitignore` 是最后一道防误操作的护栏，不是安全扫描工具。

### 文本信号

可以用 `rg` 搜索邮箱、手机号、密钥字段和已知实体名称，但不要把搜索结果粘贴到公开日志：

```bash
rg -n --hidden -g '!/.git/' '(api[_-]?key|secret|token|password|BEGIN .*PRIVATE KEY)'
rg -n --hidden -g '!/.git/' '[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,}'
```

正则只能发现部分格式。仍需人工检查语义、文件名和图像内容。

### 二进制与元数据

- PDF：检查文档属性、作者、标题、附件、批注、隐藏层和可提取文本；
- 图片：检查 EXIF、GPS、缩略图、背景中的姓名/工牌/屏幕，以及二维码实际内容；
- Office 文件：检查作者、修订记录、批注、隐藏工作表和嵌入对象；
- 压缩包：解压后重新枚举全部文件，不依赖外层文件名判断内容。

### Git 历史

删除当前文件不会自动清除历史。公开前检查：

```bash
git log --stat --all
git rev-list --objects --all
```

如果敏感信息曾进入提交，应先撤销或轮换相关凭据，再评估历史重写。已经被第三方抓取的内容无法通过一次 force-push 保证收回。

## 本仓库的公开约定

- `examples/` 只接受合成数据，并标注 `synthetic: true`；
- 真实简历、渲染页、头像和项目工作笔记放在被忽略的本地目录，不进入版本控制；
- `html-resume-builder` 自带的姓名、联系方式和头像都是模板占位符，严格 QA 会拒绝已知占位内容；
- 发现已公开的敏感信息时，不在公开 Issue 中复述，按 [`SECURITY.md`](../SECURITY.md) 私下报告。
